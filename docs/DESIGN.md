## 1. 왜 다시 짰나 — 첫 판의 문제 (2026-08-29 실측)

첫 판은 `text()`를 `<pre>`로 감싼 한 덩어리였다. 실제로 도착한 메일에서 네 가지가 드러났다.

| # | 문제 | 결과 |
|---|------|------|
| ① | 공시마다 URL이 **제목 아래 별도 줄**로 나왔다 | 줄 수가 두 배. 그 줄은 전부 노이즈 |
| ② | 조건·공시·보조 신호·뉴스가 **같은 무게**로 보였다 | 무엇이 중요한지 알 수 없다 |
| ③ | 15종목이 **평등하게** 나열됐다 | 🔴 2건이 그 사이에 묻힌다 |
| ④ | 스캔 경로가 없다 | 처음부터 끝까지 읽어야 오늘 볼 것이 있는지 안다 |

본문 18,012자. 아침에 읽는 메일로는 길다.

## 3. 합의된 구조 (추천안 채택)

```
머리      날짜 · 한 문장 · 등급 칩
인덱스 표  전 종목: ● 종목 / 종가 / 등락 / 공시(위험·전체) / 시총    ← 한 번에 훑는 유일한 자리
구역 ●    위험 유형이 확인된 종목  N
  카드      머리 밴드(등급색) · 한 줄 판정
            공시 표 — 위험 유형 먼저, 제목이 곧 링크
            신호 조건 표 — 상위 evidence 그대로
            참고값 줄 — 시총 · 거래대금 · 이상 점수 · ⚠ 생략
구역 ○    확인된 위험 유형이 없는 종목  N
  압축 카드  조건은 "5/5" 한 줄 · 공시 3건 · 뉴스 3건 · 참고값

```

| B · 전면 표 | 카드 없이 전부 표 행 | 신호 조건 5줄이 들어갈 자리가 없다 |

## 5. 길이 예산 — 설계의 핵심 (SPEC F7b · N15)

메일 한 통이 **102,400 bytes**를 넘으면 Gmail이 `[메시지 전체 보기]`로 잘라낸다.
잘리면 꼬리의 한계 문구(R7)까지 사라지므로, 이것은 미관이 아니라 규정 문제다.

| 판 | 크기 | 무엇이 달랐나 |
|---|------|---------------|
| 첫 판 (`<pre>`) | 본문 18,012자 | 잘리지는 않았으나 읽히지 않았다 |
| 시안 1차 (전부 inline) | **149,971 bytes — 잘림** | 스타일 문자열이 줄마다 되풀이 |
| 클래스 접기 후 | 111,339 bytes — 여전히 잘림 | 평문이 15종목을 다 펼침 |
| **확정** | **78,269 bytes · 여유 24%** | 클래스 + 평문 한 줄 요약 |

**접히는 것과 접히지 않는 것**

| 접는다 (예산 초과 시) | 접지 않는다 |
|---|---|
| 위험 없는 종목의 압축 카드 (뒤에서부터) | 인덱스 표 — 전 종목 |
| 평문의 위험 없는 종목 상세 | 위험 종목 카드와 그 공시 전부 |
| 공시·뉴스 목록의 꼬리 | 한계 문구 · 요약 실패 표기 |

잘린 사실은 언제나 드러낸다 — `외 N건`, `나머지 N종목은 위 「한눈에 보기」 표에 있습니다`.

## 6. 문구 경계 (SPEC N1) — 디자인이 흔들면 안 되는 것

카드·칩·색이 늘어도 **사실 나열은 되고 판단은 안 된다**는 규칙은 그대로다.

- 등급 칩은 `위험 유형 확인 2`이지 `위험 2`가 아니다. 색은 강조일 뿐 판단이 아니다.
- 머리 밴드의 한 줄은 규칙 이름을 한국어로 적는다 (`전환사채 발행결정 1건`) — `오버행 주의`가 아니다.
- 공시·뉴스 제목은 **원문**이라 금지어가 들어 있어도 그대로 싣는다. 우리가 쓴 문장만 검사한다.

## 8. v2 — 판정·점수·수급이 들어간 레이아웃 (2026-08-30 합의)

> 시안 캔버스: <https://claude.ai/code/artifact/388d60fd-effb-4a51-82ad-32f8f953f068>
> 아트보드 둘 — **메일 v3**와 **전문 페이지(F20)**. 08/26 실데이터(씨피시스템·엔투텍)로 그렸다.
> 합의: 2026-08-30 (사용자 — 시안대로 진행). 구현: `briefing/render.py` · `briefing/page.py`.

### 왜 또 바꾸나

v2.1은 "공시를 읽기 좋게" 배치했다. v3.0에서 **목적이 바뀌었다** (SPEC §2-5) —
공시를 나열하는 것이 아니라 **차트 신호가 근거를 갖는지 판정한다.** 판정과 점수, 그리고
그 근거가 된 세 갈래(공시 본문·뉴스·수급)가 화면의 주인공이 되어야 한다.

### 메일 구조 (v2.1에서 달라지는 것만)

```
인덱스 표   종목 · 등락 · [판정] · 근거점수 ▓▓░░ 23 · 공시 · 30일수급
            ↓ 표 바로 아래  "이 점수가 보지 않는 것" 문구        ← 새로

카드       [불일치 23점] 전환사채 1건 · 잠재물량 5.10% · 공시일 외국인 순매도
           분석 발췌 2~3줄 + [전문 보기 →]                      ← 새로
           공시 3건  (정기·정형 공시 1건은 접었습니다)            ← 새로 (F16)
           공시 본문 표 — 발행금액·자금용도·전환가·잠재물량·잔액   ← 새로 (F15)
           수급 표 — 30일 누적 / 공시 당일                       ← 새로 (F17)
           23점 = 50 −8 −5 −3 −8 −6 +3                          ← 새로 (F18)
```

**구역을 등급이 아니라 판정으로 나눈다.** v2.1은 `위험 유형이 확인된 종목`으로 묶었는데,
v3.0의 물음은 "위험이 있나"가 아니라 "근거가 받치나"다. `불일치`가 전체 카드로 먼저 오고,
`정합`·`무관`은 압축 카드로 뒤에 온다.

### 확정한 결정

| # | 결정 | 이유 |
|---|------|------|
| **G8** | **판정 색** — 정합 `#0F6E5C`(초록) · 불일치 `#C9283E`(붉음) · 무관 회색 테두리 | 국내 관행상 빨강은 상승이다. 판정은 등락과 **다른 축**이라 정합만 색 계열을 뺐다. 불일치는 빨강이 직관적이라 그대로 둔다 |
| **G9** | **점수 막대** — 44px 바 + 숫자 | 숫자만 두면 60과 27의 거리가 눈에 안 들어온다. 막대는 인덱스 표에서 한 번에 훑기 위한 것이다 |
| **G10** | **메일은 발췌 2~3줄(약 150자), 전문은 링크** | 종목당 2,000자 × 15는 Gmail이 잘라낸다 (D20·N15). 실측 서술은 418~647자였다 |
| **G11** | **점수 한계 문구를 두 곳에** — 인덱스 표 바로 아래, 그리고 꼬리 | 점수는 사실보다 그럴듯해 보인다 (R20). **길이 예산을 넘겨도 접히지 않는다** |
| **G12** | **정형 공시는 `정기·정형 공시 N건`으로 접는다** (F16) | 전체의 65%다. 접힌 건수는 항상 보인다 — 조용히 숨기지 않는다 |
| **G13** | **전문 페이지는 Artifact** | 본인 계정 로그인이 있어야 열린다 — R7 v2(본인 전용)에 맞는다. 공개 링크로 두지 않는다 |

### 전문 페이지 (F20)

목차(판정·점수·글자수) → 종목마다 **분석 전문 + 근거 자료 전부**:
공시 본문 표(합계 행에 잠재 물량 누계) · 수급 30거래일(공시일 강조) · 뉴스 제목+요약 ·
검증한 차트 조건. 종목마다 점수 한계 문구를 한 번 더 적는다.

머리에 **"본인 전용 페이지입니다. 링크를 공유하지 마세요"**를 띄운다 —
판정과 점수를 남에게 배포하면 유사투자자문업 신고 대상이다 (R7 v2).

## 9. v3 — 메일은 간략히, 전문은 웹으로 (2026-08-31 사용자 지시)

사용자 지시: *"메일은 간략하게 보내고 전문 페이지는 벨셀로 배포해서 유도하는 방식으로,
배포 페이지에는 이 내용이 투자권고가 아니라 참고용 테스트임을 강조."*

### 메일에서 뺀 것

| 뺀 것 | 어디로 |
|-------|--------|
| 공시 본문 표 (발행금액·자금용도·전환가·잠재물량) | 웹 |
| 수급 30일 표 | 웹 |
| 뉴스 목록 | 웹 (메일은 건수만) |
| 분석 발췌 150자 → **90자** | 전문은 웹 |
| 공시 목록 4건 → **3건** | 웹 |

머리에 `공시 본문 · 수급 30일 · 뉴스 · 분석 전문은 웹에서 봅니다 →` 한 줄을 둔다.
길이 예산도 45,000 → **28,000자**로 낮췄다 — 예산이 크면 남는 자리를 카드로 채워 다시 길어진다.

**실측**: 보이는 글자 8,253 → **3,250자**, 전송 77,560 → **47,992 bytes**(여유 24% → 53%).

### 전문 페이지 — 공개 URL이 됐다

Artifact(본인 계정 로그인 필요)에서 **Vercel 정적 배포**로 바뀌었다. URL을 아는 사람은
누구나 열 수 있으므로, 성격을 오해할 수 없게 못박는다 (SPEC F20b).

| # | 결정 | 이유 |
|---|------|------|
| **G14** | 최상단에 **`투자 권고가 아닙니다 · 참고용 테스트입니다`** 띠 | 페이지를 열면 이것부터 보인다 |
| **G15** | 바로 아래 **무엇인가 / 무엇이 아닌가 / 점수의 한계** 세 줄 | "자동화 실험" · "추천 아님, 정확성 보증 없음" · F18 한계 |
| **G16** | **종목마다 한 번 더** | 목차를 건너뛰고 스크롤로 들어온 사람도 본다 |
| **G17** | `noindex, nofollow` | 검색에 걸리면 "링크를 아는 사람만"이 무너진다 |
| **G18** | **배치가 HTML을 만들어 올린다** (DB 미연결) | 웹 번들에 anon 키를 넣지 않는다 — 상위 프로젝트에서 키 범위가 문제된 적이 있다 |

**한계를 적어 둔다** (R7 v3): 이 조치들은 오인을 줄일 뿐 공개 URL이라는 사실을 바꾸지 못한다.
링크를 불특정 다수에게 알리는 순간 경계를 넘는다.
